# Loans and EMIs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Track loans taken and given (EMI or monthly interest): what is still owed, the next instalment, the principal/interest split of every payment, and their effect on accounts and net worth, offline and synced.

**Architecture:** Two new synced tables, `loans` and `loan_payments`, are the source of truth. One local SQLite transaction per operation writes them plus the derived `transactions` rows and the loan's one reminder (deterministic uuid v5 ids), queued parent first, exactly as `SplitRepository.saveExpense` does. All money rules live in pure Dart in `LoanCalculator` (exact `Decimal`, rounded to paisa).

**Tech Stack:** Flutter, GetX, sqflite (the app reads only the local database), Supabase (Postgres + RLS), `decimal` 3.2.6, `uuid` v5.

**Spec:** `docs/superpowers/specs/2026-11-11-loans-emi-design.md`. Read it with this plan. Where they differ, this plan wins: it records the decisions below, taken while checking the spec against the code.

## Decisions this plan adds to the spec

- **Remaining EMIs.** With no live `extra` payment, the instalments left are `tenure_months − live scheduled payments` (at least 1 while something is owed), and the last one takes exactly the outstanding. With an `extra` payment they are `ceil(ln(E / (E − O·r)) / ln(1 + r) − 1e-9)` (doubles; `ceil(O / E)` when r = 0). Reason: the EMI is rounded to paisa, so counting from the EMI alone gives a 61st payment of a few paise on 1,454 of 3,000 random fresh loans; counting from the tenure ends every fresh loan on its tenure (checked in Python, scratch script, 2,000 loans).
- **Next due date of a `monthly_interest` loan** is the first anniversary of `start_date` after the latest live payment (or after the start when there is none), not "after today": it needs no clock, and an unpaid month stays overdue instead of silently moving on.
- **Back-dated payments are refused.** A payment cannot be dated before the latest live payment or before `start_date`; otherwise the stored splits of later payments go stale, which the spec forbids.
- **Payment limits:** the principal part can never exceed the outstanding; for `monthly_interest` the amount can also not exceed outstanding + unpaid interest. The interest part of an EMI or a closing payment is not capped (it is the bank's figure, and a foreclosure charge goes there).
- **Reminder tap.** A loan reminder's notification payload is `loan:<loan id>`, so a tap opens the payment form directly. The in-app reminder detail of a loan reminder shows **Record payment** and hides Edit. The reminder carries no `contact_id`, so no WhatsApp button (out of scope in the spec).
- **`loan_id` is sent to the server only when set** (`TransactionModel` and `ReminderModel` `toJson`), so plain transactions and reminders keep syncing on a server where the migration is not applied yet.
- Derived rows have `contact_id` null: a loan never touches the khata.

## Global Constraints

- Money is `Decimal` in Dart, `numeric(18, 2)` on the server, TEXT in SQLite. Never `double` for money (the `ln` above only counts months), never SQL `SUM`. At most 2 decimals.
- Rounding: intermediate values at 30 decimal places (`.toDecimal(scaleOnInfinitePrecision: 30)`, and `.round(scale: 30)` after each multiplication of `(1 + r)^n`), money rounded with `.round(scale: 2)` (half up on positive values).
- Ids: `const Uuid().v5(Namespace.url.value, '<name>')` as in `lib/domain/services/split_ids.dart`. Names: `loan:<loan id>`, `loan-payment:<payment id>:principal`, `loan-payment:<payment id>:interest`, `loan-reminder:<loan id>`. Every write is an upsert on its id.
- Soft deletes only (`deleted_at` + `tombstone()` + a `SyncOperation.delete` queue item), using the `_tombstoneLive` / `_enqueue` / `_row` helpers copied from `SplitRepository`.
- Local database only: `LoanRepository` has no Supabase path; with a null database every method throws `const DatabaseFailure()`.
- Migration `supabase/migrations/20261111090000_loans.sql`; the user applies it by hand. Local `databaseVersion` 9 → 10.
- Every successful write from a controller calls `DataChangeNotifier.markChanged()` (Home, lists, khata and the reminders' device notifications reload from it).
- A `transactions` row with `loan_id` is changed only through its loan.
- Every user-visible string is an English key with `.tr`, in both `lib/core/translations/hinglish.dart` (use "loan", "EMI", "byaaj" for interest, "mool" for principal) and `hindi.dart` (ऋण, किस्त, ब्याज, मूलधन). Calculator and repository messages are plain English keys added to both maps. Each new view file goes into `translatedFiles` in `test/core/translations/translation_coverage_test.dart`.
- New files are `dart format`-clean; existing files are formatted only if they were clean before (`dart format --output=none --set-exit-if-changed <file>`).
- Commit only the current task's files (`git add <paths>`); messages end with a blank line and `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Do not push.
- `flutter analyze` stays at "No issues found!" and the whole suite stays green after every task.
- `CLAUDE.md` rules: no data access or money math in widgets; controllers hold presentation state only; destructive actions confirm; loading, empty, error and offline states; docs and migration with every schema change.

### Task 2: Monthly interest, payment splits, status and validation

**Files:**
- Modify: `lib/domain/services/loan_calculator.dart`, `docs/05_FINANCIAL_LOGIC.md`
- Test: `test/domain/loan_calculator_test.dart`

**Interfaces:**
- Consumes: Task 1.
- Produces on `LoanCalculator`:
  - `static Decimal accruedInterest(Loan loan, List<LoanPayment> payments, DateTime asOf)` — `monthly_interest` only: month k (k ≥ 1) is complete when `addMonths(startDate, k) <= dateOnly(asOf)`; its interest is `monthlyInterest(principal − principal parts of payments dated on or before addMonths(startDate, k − 1))`.
  - `static Decimal unpaidInterest(Loan loan, List<LoanPayment> payments, DateTime asOf)` — accrued minus the interest parts of payments dated on or before `asOf`, never below 0.
  - `static DateTime? nextDueDate(Loan loan, List<LoanPayment> payments)` — null when closed; EMI: `dueDate(loan, live scheduled payments + 1)`; monthly: the first anniversary after the latest live payment's date (or the first anniversary).
  - `static LoanPart suggest(Loan loan, List<LoanPayment> earlier, {required LoanPaymentKind kind, required DateTime paidAt, Decimal? amount, bool closing = false})` — `earlier` excludes the payment being edited. EMI `scheduled`: with no amount, the next schedule row; with an amount, interest = min(amount, `monthlyInterest(outstanding)`) and the rest principal. EMI `extra`: all principal; `closing` → amount = outstanding. Monthly: interest = min(amount, unpaid interest at `paidAt`), the rest principal; with no amount the unpaid interest, or outstanding + unpaid interest when `closing`.
  - `class LoanStatus { final Decimal outstanding, principalRepaid, interestPaid; final DateTime? nextDueDate; final Decimal? nextAmount; final int? instalmentsLeft; }` and `static LoanStatus status(Loan loan, List<LoanPayment> payments)` — `nextAmount`: EMI, the next schedule row's amount; monthly, `unpaidInterest(asOf: nextDueDate)`; `instalmentsLeft` only for EMI.
  - `static String? validateLoan(Loan loan)` — the first message, in this order: `'Give the loan a name'` (blank); `'Choose an account'` (empty id); `'Amount must be more than zero'` (principal <= 0); `'Amounts can have at most 2 decimals'` (principal or EMI); `'Interest rate must be between 0% and 60% a year'` (EMI) or `'Interest rate must be between 0% and 5% a month'` (monthly) for a rate outside 0..60; EMI only: `'Tenure must be 1 to 480 months'`, `'Enter the EMI'` (null or <= 0), `"The EMI does not cover the first month's interest"` (rate > 0 and EMI <= `monthlyInterest(principal)`), `'Choose the first EMI date'`, `'The first EMI cannot be before the loan starts'`.
  - `static String? validatePayment(Loan loan, List<LoanPayment> earlier, LoanPayment payment)` — in order: `'Amount must be more than zero'`; `'Amounts can have at most 2 decimals'`; `'Principal and interest must add up to the amount'` (also for a negative part); `'A payment cannot be dated before the previous one or the loan start'`; `'This loan is already repaid'` (outstanding of `earlier` is 0); `'This is more than the principal still owed'`; monthly only: `'This is more than is owed'` (amount > outstanding + unpaid interest at `paidAt`).
